# diskOS Disco! 2.6.1

A fix for Bluetooth headphones dropping during playback in 2.6.0.

## Bluetooth

- **Headphones no longer drop mid-song.** Every few seconds Disco checks the headphones' audio link. When the Disc
  was busy (a cover loading, a skip, or simply the screen being off), that check could answer late, and 2.6.0 took a
  late answer for "the link is gone". It then set the connection up again, which restarts the player's Bluetooth
  service: the headphones dropped, reconnected and switched codec again. Now a late answer changes nothing; only
  three checks in a row that really find no link (9 seconds) count as a disconnect.

Everything else is as in [2.6.0](v2.6.0.md).

> **Testing:** the fix is covered by an automatic test that fails on 2.6.0 and passes on 2.6.1; it was not yet
> tried on a Disc before release.

## Installing and updating

- **Already on diskOS Disco! 1.4.1 or newer?** Update from the SD card: download `mq_ui`, sign it with your own
  keys and copy the `diskos-update` folder to the card ([how](../UPDATING.md)). Your settings, music and stats stay.
- **New install?** Start from **FiiO's stock V2.57 firmware** (recommended). Installing over upstream diskOS or
  another diskOS build is not supported and can be buggy; restore stock first. See [Install](../../README.md#install).
- **Windows:** Unsupported, but working as intended: confirmed several times by users, installs and SD updates included.

## After updating

- **Settings > System > About** shows **2.6.1**.
- The new version starts as a **trial**: play some music or tap **Keep** to keep it. If it doesn't start properly,
  the Disc goes back to the previous version by itself, or choose **Go back**.

<details>
<summary>Technical notes</summary>

`bt_autoroute_poll_cb` now calls `run_cap_to` directly: a timed-out `bluealsa-cli list-pcms` probe (-1) returns
without touching any state; only three consecutive completed probes without an A2DP PCM clear the auto-route latch,
cancel a pending codec switch and call `ui_route_forget("link gone")`. In 2.6.0 two timed-out probes (read as empty by
`run_cap_bounded`) forgot the route, and the following re-route's 06c1 restarted bluetoothd/BlueALSA. Test:
`ui/tests/bt_autoroute_test.py`. Built with the GCC 11.2 MIPS toolchain; build record in `payload/mq_ui.build.json`.

</details>
